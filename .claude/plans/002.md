# Login + Admin-Approved Purchase + Revenue Dashboard + Cloud Save

## (better-auth + Turso + Drizzle, migration-based)

## Context

Easy ABC ตอนนี้ **client-only ล้วน** — ทุก state (ดาว/พลังงาน/การซื้อ) อยู่ localStorage ไม่มี identity
→ ล้าง localStorage หรือเปลี่ยนเครื่อง = การซื้อหาย · การซื้อเป็น auto-approve (กดยืนยัน = ปลดล็อกทันที ไม่เช็คเงิน)

พี่ต้องการเพิ่ม **backend ตัวแรก**: login Google (better-auth) + เก็บ user/การซื้อ/ความคืบหน้าลง Turso (libSQL) ผ่าน Drizzle
เพื่อผูกการซื้อกับ identity แล้วกู้คืนข้ามเครื่องได้ **และเพราะตอนนี้รู้ identity แล้ว → เปลี่ยนเป็นระบบ admin อนุมัติการซื้อ + มีหน้า admin และ dashboard สรุปรายได้**

### ⚠️ การเปลี่ยนโมเดลสำคัญ (พี่สั่ง override ของเดิม)

**auto-approve → admin-approve**: เดิมกดยืนยัน = ปลดล็อกทันที. ใหม่: กดยืนยัน = สร้าง order สถานะ `pending`
(ยังไม่ปลดล็อก) → admin เช็คว่าเงินเข้า PromptPay จริง → กด approve → `approved` → ผู้ใช้ถึงปลดล็อก

- แลกมาด้วย UX: ผู้เล่นต้องรอ admin อนุมัติ (แสดงสถานะ "⏳ รออนุมัติ" ชัดเจน) ไม่ปลดทันที
- ต้องอัปเดต decision memory (`easy-abc-game-decisions.md`) + ทำ ADR (`/new-adr`) เพราะกลับด้านการตัดสินใจที่เคยล็อก

### การตัดสินใจที่ล็อกกับพี่แล้ว

- Provider: **Google อย่างเดียว** · สิทธิ์ admin: **better-auth admin plugin** (role/ban ในตาราง user + guard สำเร็จรูป)
- Sync ขึ้น server: **การซื้อ (orders) + progress (ดาว)** — พลังงาน/สถิติ/ธีม/เสียง คง local
- บังคับ login: **เฉพาะตอนซื้อ/กู้คืน** — เล่นฟรี anonymous ได้เหมือนเดิม
- **Migration จริง**: drizzle-kit `generate` → ไฟล์ SQL versioned commit ลง repo + `migrate` runner (ไม่ใช่ push เฉยๆ)
- หน้า admin **ใช้ app shell/ธีม/component เดียวกับเกม** (route group `(admin)` แชร์ root layout `app/layout.tsx` เดิม)

### สิ่งที่พี่ต้องเตรียมเอง (ผม scaffold + placeholder + `.env.example` ให้)

- Turso DB (URL + token) — dev ใช้ `file:./dev.db` แทนได้ · Google OAuth client (id/secret) + redirect `${APP_URL}/api/auth/callback/google` · ตั้ง env บน Vercel · แต่งตั้ง admin คนแรก (seed/SQL — ดูเฟส 3)

---

## หลักการ merge (ไม่มี conflict)

- **orders**: union ตาม `productId`; entitlement นับเฉพาะ order สถานะ `approved`
- **progress (ดาว)**: best-of ต่อ `(game, level)`
- Sync two-way idempotent ตอนมี session → pull → merge → push · ของแถม: ซื้อ/เล่นตอน anonymous แล้ว login ทีหลัง = claim เข้า account อัตโนมัติ

## เฟส 1 — Infra + Auth + Migration system

**Deps (npm):** `better-auth` (มี admin plugin ในตัว), `drizzle-orm`, `@libsql/client` + dev `drizzle-kit`

**DB + migration (server-only, นอก domain):**

- `src/server/db/client.ts` [ใหม่] — libSQL client + `drizzle(db, { schema })` อ่าน `TURSO_DATABASE_URL`/`TURSO_AUTH_TOKEN` (dev fallback `file:./dev.db`)
- `src/server/db/schema.ts` [ใหม่] — Drizzle schema:
  - ตาราง better-auth + **admin plugin**: `user` (มี `role`,`banned`,`banReason`,`banExpires`), `session` (`impersonatedBy`), `account`, `verification` — gen ด้วย `npx @better-auth/cli generate`
  - `purchase`: `id` PK · `userId` FK · `productId` · `productName` · `amountThb` · `status` (`'pending'|'approved'|'rejected'`) · `createdAt` · `approvedAt?` · `approvedBy?` (admin userId) · `note?`
  - `game_state`: `userId` PK · `progress` (JSON = starsByGame) · `updatedAt`
- `drizzle.config.ts` [ใหม่] — dialect `turso`/libsql, `schema: ./src/server/db/schema.ts`, `out: ./drizzle`
- `drizzle/` [ใหม่] — โฟลเดอร์ migration SQL ที่ generate ออกมา (commit ลง repo)
- `src/server/db/migrate.ts` [ใหม่] — runner ใช้ `migrate()` จาก `drizzle-orm/libsql/migrator` (สำหรับ prod/CI)
- `package.json` [แก้] — scripts: `db:generate` (drizzle-kit generate), `db:migrate` (apply), `db:studio`

**better-auth:**

- `src/server/auth.ts` [ใหม่] — `betterAuth({ database: drizzleAdapter(db,{provider:"sqlite"}), plugins:[admin()], socialProviders:{ google:{...} }, baseURL: process.env.APP_URL ?? "https://easy-abc.easy-ai.online" })`
- `src/server/is-admin.ts` [ใหม่] — helper `requireAdmin(session)` / `isAdmin(session)` (เช็ค `role === "admin"`) — จุดเดียว สลับ logic ได้
- `app/api/auth/[...all]/route.ts` [ใหม่] — `toNextJsHandler(auth)` (อ่าน `node_modules/next/dist/docs/01-app/01-getting-started/15-route-handlers.md` ก่อน)
- `src/presentation/lib/auth-client.ts` [ใหม่] — `createAuthClient({ plugins:[adminClient()] })` → export `signIn`,`signOut`,`useSession`

**UI + gate:**

- `src/presentation/components/auth-panel.tsx` [ใหม่] — logout: ปุ่ม "เข้าสู่ระบบด้วย Google"; login: ชื่อ/อีเมล + ออกจากระบบ + "กู้คืนการซื้อ"; ถ้า admin โชว์ลิงก์ "แผงผู้ดูแล". guard `useMounted()`
- `src/presentation/components/settings-panel.tsx` [แก้] — เพิ่ม section บัญชี (`<AuthPanel/>`)
- `.env.local` (gitignored) + `.env.example` [ใหม่]: `TURSO_DATABASE_URL`,`TURSO_AUTH_TOKEN`,`BETTER_AUTH_SECRET`,`APP_URL`,`GOOGLE_CLIENT_ID`,`GOOGLE_CLIENT_SECRET`
- `eslint.config.mjs` [แก้] — เพิ่ม `drizzle-orm`,`@libsql/*`,`better-auth` เข้า no-restricted-imports ของ `src/domain/**`

**Deliverable:** login Google → session ค้าง reload → เห็นชื่อใน settings → logout · migration generate/apply ลง `file:./dev.db` ได้

## เฟส 2 — การซื้อขึ้น server (pending) + restore

**Port + user adapter (role-split ตาม skill hexagonal):**

- `src/domain/ports/purchase.port.ts` [ใหม่] — `Order` (มี `status`), `interface PurchaseRepository { listMine(): Promise<Result<Order[]>>; add(o: NewOrder): Promise<Result<Order>> }` (bare, ไม่ import framework/DB)
- `src/adapters/purchases/turso.adapter.ts` [ใหม่] — `implements PurchaseRepository` รับ `userId` (server-only), `add` = insert สถานะ `pending`, map row↔domain, error→`err()`
- `src/adapters/purchases/memory.adapter.ts` [ใหม่] + `index.ts` `createPurchaseRepo(userId)` [ใหม่]
- `test-contracts/purchase.contract.ts` [ใหม่] + wire memory เข้า `repos.test.ts` [แก้]

**Server actions:** `app/actions/purchase.ts` [ใหม่] `"use server"`:

- `recordPurchase(productId)` — validate session (ไม่มี→`err`); โหลด product ผ่าน `createProductRepo()`; `createPurchaseRepo(userId).add(...)` = **pending** (ไม่ปลดล็อกทันที); คืน `Result<Order>`
- `listMyPurchases()` — คืน order ทั้งหมดของ user (ทุกสถานะ ให้ UI แยก approved/pending)

**Merge (pure):** `src/domain/services/sync.ts` [ใหม่] — `mergeOrders(local, server): Order[]` + `sync.test.ts`

**Store + UI:**

- `src/presentation/stores/entitlement.store.ts` [แก้] — `owns()`/`hasMode()`/`hasBundle()` นับเฉพาะ `status==='approved'`; เพิ่ม `hydrateFromServer(orders)` + เก็บ pending ไว้โชว์สถานะ
- `src/presentation/components/purchase-panel.tsx` [แก้] — กดยืนยัน: ยังไม่ login → เปิด sign-in ก่อน; login แล้ว → `recordPurchase()` → success modal เปลี่ยนเป็น **"⏳ ส่งคำสั่งซื้อแล้ว รอผู้ดูแลอนุมัติ"** (ไม่ใช่ "ปลดล็อกสำเร็จ"); โชว์ order pending ในรายการ
- `src/presentation/lib/use-sync.ts` [ใหม่] — มี session → `listMyPurchases()` → `hydrateFromServer()`; ปุ่ม "กู้คืนการซื้อ" เรียก hook นี้ (ดึงสถานะล่าสุด — ถ้า admin เพิ่ง approve จะปลดล็อกตอน sync/เปิดแอป)

**Deliverable:** login → ซื้อ → เห็น "รออนุมัติ" ยังเล่นโหมดพรีเมียมไม่ได้ · order ตอน anonymous ถูก claim เข้า account ตอน login

## เฟส 3 — Admin: อนุมัติการซื้อ + Dashboard รายได้ (แชร์ app shell)

**Admin adapter (role-split — server-only, เห็นทุก user):**

- `src/domain/ports/admin-purchase.port.ts` [ใหม่] — `interface AdminPurchaseRepository { listAll(); listByStatus(s); approve(orderId, adminId); reject(orderId, adminId, note?); }` คืน `Result`
- `src/adapters/purchases/admin.adapter.ts` [ใหม่] + เพิ่ม factory `createAdminPurchaseRepo()` ใน `index.ts` (server-only)
- `test-contracts/admin-purchase.contract.ts` [ใหม่] (memory) เข้า `repos.test.ts`

**Revenue summary (pure, domain):**

- `src/domain/services/revenue.ts` [ใหม่] — `summarizeRevenue(orders): { totalThb; approvedCount; pendingCount; byProduct: {productId,name,count,totalThb}[]; recent: Order[] }` + `revenue.test.ts`

**Server actions:** `app/actions/admin.ts` [ใหม่] `"use server"` — ทุกฟังก์ชัน `requireAdmin(session)` ก่อน: `approveOrder(id)`, `rejectOrder(id, note?)`, `getPendingOrders()`, `getRevenueSummary()`

**หน้า admin (แชร์ shell เกม):**

- `app/(admin)/layout.tsx` [ใหม่] — server component: เช็ค session + `requireAdmin` ไม่ผ่าน → `notFound()`; render top bar admin แต่ **สืบทอด root `app/layout.tsx` เดิม** (ธีม/ฟอนต์/ThemeScript/tokens ใช้ร่วม) + ใช้ component/สไตล์เดียวกับเกม (card/ปุ่ม semantic tokens — ห้าม hardcode สี)
- `app/(admin)/admin/page.tsx` [ใหม่] — Dashboard: การ์ดสรุป (ยอดรวม฿, จำนวนอนุมัติ, รอดำเนินการ), แยกตาม product, ออเดอร์ล่าสุด (ข้อมูลจาก `getRevenueSummary()`)
- `app/(admin)/admin/orders/page.tsx` [ใหม่] — คิวอนุมัติ: list pending (ผู้ซื้อ/สินค้า/ยอด/เวลา) + ปุ่ม อนุมัติ/ปฏิเสธ (client component เรียก server action → refresh)

**แต่งตั้ง admin คนแรก (bootstrap):**

- `src/server/db/seed-admin.ts` [ใหม่] หรือ npm script `db:make-admin` — set `role='admin'` ให้อีเมลที่กำหนด (ครั้งแรกทำผ่าน SQL/seed เพราะยังไม่มี admin ไปตั้งให้คนอื่น); หลังจากนั้น admin ตั้งคนอื่นผ่าน better-auth admin API ได้

**Deliverable:** admin เข้า `/admin` เห็นยอดรวม + คิว pending → กด approve → ผู้ใช้ (sync/เปิดแอป) ปลดล็อก · non-admin เข้า `/admin` → 404

- เล่นฟรี/adventure ไม่ต้อง login · level lock ยังใช้ดาว ไม่ใช่การซื้อ · พลังงาน/สถิติ/ธีม/เสียง = local
